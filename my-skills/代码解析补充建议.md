## 一、关键概念遗漏

### 1. Shared Store（共享存储）概念

**原笔记遗漏**：虽然在示例中使用了 `shared` 参数，但没有明确解释它的作用。

**补充说明**：

#### 什么是 Shared Store？
Shared Store 是 PocketFlow 的核心通信机制，是一个**全局共享的数据存储**（通常是字典），所有节点通过它交换数据。

```python
# Shared Store 的典型结构
shared = {
    "input_data": "原始数据",
    "processed_data": None,
    "results": [],
    "metadata": {}
}
```

#### 为什么需要 Shared Store？
1. **节点解耦**：节点之间不直接传递数据，而是通过共享存储
2. **状态持久化**：整个流程的中间状态都保存在 shared 中
3. **灵活性**：任何节点都可以访问或修改共享数据

#### 三步执行模型与 Shared Store 的关系

```python
class MyNode(Node):
    def prep(self, shared):
        """从 shared 读取数据"""
        return shared["input_data"]

    def exec(self, prep_res):
        """纯计算，不访问 shared"""
        return process(prep_res)  # 只处理 prep_res

    def post(self, shared, prep_res, exec_res):
        """将结果写回 shared"""
        shared["results"] = exec_res
        return "default"  # 返回 action
```

**关键原则**：
- ✅ `prep()` 从 shared **读取**
- ✅ `exec()` **不访问** shared（保持纯函数）
- ✅ `post()` 向 shared **写入**

### 2. Action 机制的深入解释

**原笔记不足**：提到了条件分支，但没有详细解释 Action 的完整工作流程。

**补充说明**：

#### Action 的完整生命周期

```python
# 1. post() 返回 action 字符串
class CheckNode(Node):
    def post(self, shared, prep_res, exec_res):
        if exec_res > 0:
            return "positive"  # 这就是 action
        return "negative"

# 2. Flow 根据 action 查找下一个节点
class Flow:
    def get_next_node(self, curr, action):
        nxt = curr.successors.get(action or "default")
        # 从当前节点的 successors 字典中查找
        return nxt

# 3. 连接时指定 action
check - "positive" >> positive_handler
check - "negative" >> negative_handler

# 实际上是：
check.successors["positive"] = positive_handler
check.successors["negative"] = negative_handler
```

#### Action 的特殊值

1. **"default"**：`post()` 返回 `None` 时，默认使用 "default"
2. **自定义字符串**：可以是任何字符串，如 "success", "error", "retry" 等

#### _ConditionalTransition 的作用

```python
class _ConditionalTransition:
    def __init__(self, src, action):
        self.src = src      # 源节点
        self.action = action  # 要匹配的 action

    def __rshift__(self, tgt):
        # node - "success" >> next_node
        # 等价于：node.next(next_node, action="success")
        return self.src.next(tgt, self.action)
```

**这个类的存在是为了实现优雅的语法**：
```python
# 方式1：直观但繁琐
node.next(next_node, action="success")

# 方式2：优雅的操作符重载
node - "success" >> next_node
```

### 3. copy.copy() 的关键作用

**原笔记遗漏**：Flow 的 `_orch()` 方法中大量使用 `copy.copy()`，但没有解释为什么。

**补充说明**：

#### 为什么要复制节点？

```python
def _orch(self, shared, params=None):
    curr = copy.copy(self.start_node)  # 🔑 关键：复制起始节点
    # ...
    while curr:
        # ...
        curr = copy.copy(self.get_next_node(curr, last_action))  # 🔑 每次都复制
```

**原因**：避免节点状态污染

```python
# 问题场景：不使用 copy.copy()
class CounterNode(Node):
    def __init__(self):
        super().__init__()
        self.count = 0

    def exec(self, prep_res):
        self.count += 1  # 修改节点状态
        return self.count

# 第一次运行
flow.run(shared)  # count = 1

# 第二次运行
flow.run(shared)  # count = 2（❌ 不符合预期！应该是1）
```

**使用 copy.copy() 后**：
- 每次运行都使用节点的**浅拷贝**
- 节点的实例变量会被复制
- 避免了状态累积

**注意**：是**浅拷贝**，不是深拷贝
- 节点对象本身被复制
- 但节点引用的对象（如 shared）不会被复制
- 这正是我们想要的：shared 需要共享，节点状态需要隔离

### 4. Params vs Shared Store

**原笔记不足**：没有明确区分 `params` 和 `shared` 的使用场景。

**补充说明**：

#### Params 的设计目的

```python
class BaseNode:
    def __init__(self):
        self.params = {}      # 节点参数
        self.successors = {}  # 后继节点
```

#### 两者的区别

| 特性 | Shared Store | Params |
|------|--------------|--------|
| **作用域** | 全局（所有节点共享） | 局部（单个节点） |
| **可变性** | 可变（节点可以修改） | 不可变（只读） |
| **传递方式** | 通过 run() 传入 | 通过 set_params() 设置 |
| **主要用途** | 数据存储和传递 | 任务标识和配置 |

#### 实际使用场景

**Shared Store**：存储和传递数据
```python
shared = {
    "input": "待处理数据",
    "output": None
}

class ProcessNode(Node):
    def prep(self, shared):
        return shared["input"]  # 读取

    def post(self, shared, prep_res, exec_res):
        shared["output"] = exec_res  # 写入
```

**Params**：标识任务（主要用于 BatchFlow）
```python
class ProcessFile(Node):
    def prep(self, shared):
        filename = self.params["filename"]  # 读取参数
        return shared["files"][filename]

    def post(self, shared, prep_res, exec_res):
        filename = self.params["filename"]
        shared["results"][filename] = exec_res

# BatchFlow 会为每个文件设置不同的 params
class ProcessAllFiles(BatchFlow):
    def prep(self, shared):
        return [{"filename": f} for f in shared["files"].keys()]
```

### 1. 重试机制的细节

**原笔记不足**：提到了重试，但没有解释 `cur_retry` 的作用。

**补充说明**：

```python
class Node(BaseNode):
    def _exec(self, prep_res):
        for self.cur_retry in range(self.max_retries):
            try:
                return self.exec(prep_res)
            except Exception as e:
                if self.cur_retry == self.max_retries - 1:
                    return self.exec_fallback(prep_res, e)
                if self.wait > 0:
                    time.sleep(self.wait)
```

#### cur_retry 的作用

1. **作为实例变量**：`self.cur_retry` 可以在 `exec()` 中访问
2. **用于自适应逻辑**：可以根据重试次数调整策略

**使用示例**：
```python
class SmartRetryNode(Node):
    def exec(self, prompt):
        # 第一次尝试用快速模型
        if self.cur_retry == 0:
            model = "gpt-3.5-turbo"
        # 重试时用更强大的模型
        else:
            model = "gpt-4"

        return call_llm(prompt, model=model)
```

#### 重试等待时间的指数退避

**原实现**：固定等待时间
```python
if self.wait > 0:
    time.sleep(self.wait)  # 每次都等待相同时间
```

**改进建议**：指数退避
```python
class SmartNode(Node):
    def _exec(self, prep_res):
        for self.cur_retry in range(self.max_retries):
            try:
                return self.exec(prep_res)
            except Exception as e:
                if self.cur_retry == self.max_retries - 1:
                    return self.exec_fallback(prep_res, e)

                # 指数退避：1秒 → 2秒 → 4秒 → 8秒...
                wait_time = self.wait * (2 ** self.cur_retry)
                time.sleep(wait_time)
```

### 2. BatchNode 的执行细节

**原笔记不足**：没有明确说明 `prep()` 和 `post()` 的参数差异。

**补充说明**：

#### BatchNode 的完整执行流程

```python
class MyBatchNode(BatchNode):
    def prep(self, shared):
        # 返回可迭代对象（列表/生成器）
        return [1, 2, 3, 4, 5]

    def exec(self, item):
        # 对每个元素执行一次
        # 被调用 5 次
        return item * 2

    def post(self, shared, prep_res, exec_res_list):
        # 注意：第三个参数是 exec_res_list（列表）
        # 不是 exec_res！
        print(exec_res_list)  # [2, 4, 6, 8, 10]
```

**关键区别**：

| 方法 | Node | BatchNode |
|------|------|-----------|
| prep() 返回值 | 任意类型 | **可迭代对象** |
| exec() 调用次数 | 1次 | **N次**（N为元素个数） |
| post() 第三参数 | exec_res | **exec_res_list**（列表） |

#### BatchNode 的实现原理

```python
class BatchNode(Node):
    def _exec(self, items):
        # items 是 prep() 返回的可迭代对象
        return [
            super(BatchNode, self)._exec(i)  # 调用父类的 _exec
            for i in (items or [])
        ]
```

**逻辑分解**：
1. 遍历 `items` 中的每个元素 `i`
2. 对每个 `i` 调用 `Node._exec(i)`
   - `Node._exec()` 会调用 `self.exec(i)`（带重试机制）
3. 将所有结果收集到列表中返回

### 3. 异步并行的实现差异

**原笔记不足**：没有区分 AsyncBatchNode 和 AsyncParallelBatchNode。

**补充说明**：

#### AsyncBatchNode - 顺序异步

```python
class AsyncBatchNode(AsyncNode, BatchNode):
    async def _exec(self, items):
        # 顺序执行（一个接一个）
        return [await super(AsyncBatchNode, self)._exec(i) for i in items]
```

**执行流程**：
```
item1 → 等待完成 → item2 → 等待完成 → item3 → 等待完成
总时间 = T1 + T2 + T3
```

#### AsyncParallelBatchNode - 并行异步

```python
class AsyncParallelBatchNode(AsyncNode, BatchNode):
    async def _exec(self, items):
        # 并行执行（同时启动）
        return await asyncio.gather(
            *(super(AsyncParallelBatchNode, self)._exec(i) for i in items)
        )
```

**执行流程**：
```
item1 ──┐
item2 ──┼──> 并发执行 ──> 等待全部完成
item3 ──┘
总时间 ≈ max(T1, T2, T3)
```

#### 性能对比

假设处理 3 个文件，每个需要 2 秒：

| 类型 | 执行方式 | 总时间 |
|------|---------|--------|
| BatchNode | 同步顺序 | 6秒 |
| AsyncBatchNode | 异步顺序 | 6秒 |
| AsyncParallelBatchNode | 异步并行 | **约2秒** |

**注意**：
- AsyncBatchNode 虽然是异步，但仍然是顺序执行
- 只有 AsyncParallelBatchNode 才能实现真正的并行加速

### 4. AsyncFlow 的混合执行机制

**原笔记不足**：提到了同步/异步混合，但没有解释实现细节。

**补充说明**：

#### 混合执行的实现

```python
class AsyncFlow(Flow, AsyncNode):
    async def _orch_async(self, shared, params=None):
        curr = copy.copy(self.start_node)
        p = params or {**self.params}
        last_action = None

        while curr:
            curr.set_params(p)

            # 🔑 关键：判断节点类型
            if isinstance(curr, AsyncNode):
                last_action = await curr._run_async(shared)  # 异步执行
            else:
                last_action = curr._run(shared)  # 同步执行

            curr = copy.copy(self.get_next_node(curr, last_action))

        return last_action
```

#### 使用示例

```python
class SyncDataLoad(Node):
    """同步节点：从本地读取"""
    def exec(self, prep_res):
        with open("data.txt") as f:
            return f.read()

class AsyncAPICall(AsyncNode):
    """异步节点：调用 API"""
    async def exec_async(self, prep_res):
        return await call_api_async(prep_res)

class SyncSaveResult(Node):
    """同步节点：保存到本地"""
    def exec(self, prep_res):
        with open("result.txt", "w") as f:
            f.write(prep_res)

# 混合流程：同步 → 异步 → 同步
async_flow = AsyncFlow()
async_flow.start(SyncDataLoad()) >> AsyncAPICall() >> SyncSaveResult()

# 运行
await async_flow.run_async({})
```

**关键点**：
1. AsyncFlow 可以包含同步节点
2. 同步节点会在异步上下文中**阻塞执行**
3. 如果同步节点很慢，会影响整体性能

### 改进 2：条件分支示例应包含循环

```python
# === 带重试循环的条件分支工作流 ===

class ValidateNode(Node):
    """验证数据质量"""

    def prep(self, shared):
        data = shared.get("data", [])
        retry_count = shared.get("retry_count", 0)
        return data, retry_count

    def exec(self, inputs):
        data, retry_count = inputs

        # 检查数据
        if data and len(data) > 0 and all(x > 0 for x in data):
            return {"valid": True, "message": "数据有效"}
        else:
            return {
                "valid": False,
                "message": f"数据无效（第 {retry_count + 1} 次检查）"
            }

    def post(self, shared, prep_res, exec_res):
        if exec_res["valid"]:
            print(f"✓ {exec_res['message']}")
            return "valid"
        else:
            print(f"✗ {exec_res['message']}")

            # 检查重试次数
            retry_count = shared.get("retry_count", 0)
            if retry_count < 3:
                return "retry"  # 重试
            else:
                return "invalid"  # 放弃


class FixDataNode(Node):
    """修复数据"""

    def prep(self, shared):
        return shared["data"]

    def exec(self, data):
        # 修复：将所有负数改为正数
        fixed = [abs(x) if x < 0 else x for x in data]
        return fixed

    def post(self, shared, prep_res, exec_res):
        # 更新数据
        shared["data"] = exec_res

        # 增加重试计数
        shared["retry_count"] = shared.get("retry_count", 0) + 1

        print(f"✓ 数据已修复: {exec_res}")
```

```python
# 方式1：利用重试机制
class RobustAPICall(Node):

class SafeAPICall(Node):
    def exec(self, url):
        return call_api(url)  # 可能失败

        # 所有重试失败后的降级方案

            shared["api_data"] = exec_res["data"]
            return "success"
        else:
```

```python
# === 场景：批量处理多个文件 ===

class ProcessFiles(BatchNode):
    """批量处理文件"""

    def __init__(self):
        # 配置重试：每个文件失败时重试
        super().__init__(max_retries=2, wait=1)

    def prep(self, shared):
        # 返回文件列表
        return shared["files"]

    def exec(self, filepath):
        # 处理单个文件
        print(f"  处理文件: {filepath}")

        # 读取文件
        with open(filepath) as f:
            content = f.read()

        # 处理内容
        word_count = len(content.split())

        return {
            "file": filepath,
            "words": word_count
        }

    def post(self, shared, prep_res, exec_res_list):
        # exec_res_list 是所有文件的结果列表
        total_words = sum(r["words"] for r in exec_res_list)

        shared["file_stats"] = exec_res_list
        shared["total_words"] = total_words

        print(f"✓ 处理完成：{len(exec_res_list)} 个文件，共 {total_words} 词")
        return "default"


# 使用
shared = {
    "files": ["file1.txt", "file2.txt", "file3.txt"]
}

node = ProcessFiles()
node.run(shared)

#   处理文件: file1.txt
#   处理文件: file2.txt
#   处理文件: file3.txt
# ✓ 处理完成：3 个文件，共 1500 词
```

```python
import time
import asyncio

# 测试数据：10 个 URL
urls = [f"https://api.example.com/data/{i}" for i in range(10)]

async def call_api_async(url):
    await asyncio.sleep(1)
    return {"url": url, "data": "result"}


# 方案1：同步批处理（慢）
class SyncBatch(BatchNode):
    def prep(self, shared):
        return shared["urls"]

    def exec(self, url):
        return call_api_sync(url)

# 执行时间：10 秒（10 个 URL × 1 秒）


# 方案2：异步顺序批处理（仍然慢）
class AsyncBatch(AsyncBatchNode):
    async def prep_async(self, shared):
        return shared["urls"]

    async def exec_async(self, url):
        return await call_api_async(url)

# 执行时间：10 秒（虽然异步，但仍是顺序执行）


# 方案3：异步并行批处理（快！）
class AsyncParallelBatch(AsyncParallelBatchNode):
    async def prep_async(self, shared):

    async def exec_async(self, url):

    # 测试方案1

    # 测试方案3

    print(f"  耗时: {time.time() - start:.2f} 秒\n")
```
