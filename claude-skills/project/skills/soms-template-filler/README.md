# SOMS 需求模板填充器 - 使用说明

## 📋 Skill 概述

`soms-template-filler` 是一个智能模板填充工具,帮助用户将白话文需求描述快速转化为结构化的PRD文档。

**核心价值**:
- 🚀 **快速启动**: 从白话文到6个PRD文档,一步到位
- 🤖 **智能理解**: AI自动解析需求,提取关键信息
- 💬 **智能提问**: 信息不足时精准提问,避免遗漏
- 🔗 **无缝衔接**: 为 `soms-requirement-analysis` 提供完整的前置文档

---

## 🎯 使用场景

### 适用场景
✅ 你有一个需求想法,但不知道如何填写PRD
✅ 你想快速将白话文需求转为结构化文档
✅ 你想减少手动填写模板的工作量
✅ 你想为深度需求分析准备前置文档

### 不适用场景
❌ 需求过于复杂,无法用白话文简单描述
❌ 需要深度需求分析和技术方案设计(应使用 `soms-requirement-analysis`)
❌ 已有完整PRD文档,无需模板填充

## 🚀 快速开始

### 步骤1: 准备任务文件夹

从模板复制一个新的任务文件夹:

```bash
# 进入任务目录
cd .claude/mydocs/tasks/

# 复制模板文件夹
cp -r ../_TEMPLATE-任务模板 PLM-338429-引流活动商品列表

# 验证文件夹内容
ls PLM-338429-引流活动商品列表/
# 应该看到: 01-需求背景.md, 02-功能描述.md, ... , 06-注意事项.md
```

### 步骤2: 准备需求描述

用白话文描述你的需求,可以包括:

**基础信息**:
- PLM任务号 (可选,会从文件夹名提取)
- 功能是什么
- 为什么要做这个功能

**接口信息**:
- 接口路径 (如 `/api/activity/products/list`)
- 请求方法 (GET/POST/PUT/DELETE)
- 请求参数
- 返回内容

**业务信息**:
- 涉及哪些业务实体 (如商品、活动、SKU)
- 有哪些业务规则
- 业务流程是怎样的

**技术信息** (可选):
- 涉及哪些模块
- 需要调用哪些外部服务
- 数据库表设计

### 步骤3: 调用 Skill

在 Claude Code 中输入:

```
使用 soms-template-filler
任务文件夹: .claude/mydocs/tasks/PLM-338429-引流活动商品列表
需求描述:
我需要一个查询引流活动商品列表的接口,支持分页和多条件筛选。
接口路径是 /api/loss-leader/products/list,使用POST方法。
需要支持按活动ID、商品状态、SKC等条件筛选。
返回商品的基本信息、价格、库存、活动信息等。
这个功能是为了让运营人员可以查看参加引流活动的商品列表。
```

### 步骤4: 回答补充问题 (如果有)

如果信息不足,AI会智能提问,例如:

```
AI: 请问请求参数包括哪些?(例如: activityId, status, skcCode, pageNum, pageSize)
你: activityId(必填), status(可选), skcCode(可选), pageNum(必填), pageSize(必填)

AI: 请问响应字段包括哪些?(例如: productId, productName, price, stock)
你: productId, productName, skcCode, price, stock, activityId, activityName, status
```

### 步骤5: 查看填充结果

AI会自动填充6个PRD文档,并展示总结:

```
✅ 模板填充完成!

📁 已更新的文件:
- 01-需求背景.md
- 02-功能描述.md
- 03-接口文档.md
- 04-实现方案.md
- 05-技术细节.md
- 06-注意事项.md

📋 下一步建议:
1. 检查生成的文档,补充或修改不准确的部分
2. 如有遗漏的业务规则或技术细节,手动添加
3. 使用 soms-requirement-analysis Skill 进行深度需求分析
4. 使用 soms-code-implementation-v2 Skill 实现代码
```

### 步骤6: 检查和补充

打开填充好的文档,检查并补充细节:

```bash
# 查看填充结果
cat .claude/mydocs/tasks/PLM-338429-引流活动商品列表/01-需求背景.md
cat .claude/mydocs/tasks/PLM-338429-引流活动商品列表/03-接口文档.md
# ... 依次检查其他文档
```

如有不准确或遗漏的部分,直接编辑对应文件进行修改。

## 📝 需求描述示例

### 示例1: 完整详细的描述

```
使用 soms-template-filler
任务文件夹: .claude/mydocs/tasks/PLM-338431-商品价格批量更新
需求描述:
PLM任务号: PLM-338431
功能: 批量更新商品价格
需求来源: 运营部门
业务背景: 经常需要批量调整促销商品的价格,现有功能只能单个修改,效率低
目标: 支持批量更新商品价格,提升运营效率

接口路径: POST /api/products/price/batch-update
请求参数:
- productIds: 商品ID列表(必填)
- prices: 价格列表(必填),与productIds一一对应
- operatorId: 操作人ID(必填)

响应格式:
- successCount: 更新成功的商品数量
- failedList: 失败的商品ID列表及失败原因

业务规则:
- 价格必须大于0
- 价格不能超过商品原价的200%
- 需要记录价格变更历史

涉及模块: soms-service-domain, soms-service-infrastructure
涉及的业务实体: Product, PriceHistory

技术细节:
- 使用MyBatis-Plus批量更新
- 需要事务保证
- 调用PLM系统同步价格
```

**AI会直接填充所有文档,无需提问**

### 示例2: 简短的描述 (会触发提问)

**AI会提问补充关键信息**:
- "这个功能的接口路径是什么?(例如: /api/activity/status/update)"
- "涉及哪些活动状态?(例如: 待审核、进行中、已结束)"
- "请求参数包括哪些?(例如: activityId, newStatus, operatorId)"

### 示例3: 中等详细度的描述

```
使用 soms-template-filler
任务文件夹: .claude/mydocs/tasks/PLM-338432-商品库存预警
需求描述:
查询库存预警商品列表,帮助运营及时补货。

接口: GET /api/products/stock-alert/list
支持分页: pageNum, pageSize
筛选条件: warehouseId(仓库ID), alertLevel(预警级别: 低/中/高)

返回信息: productId, productName, currentStock, safeStock, alertLevel

业务规则:
- 低预警: 库存 < 安全库存 * 1.2
- 中预警: 库存 < 安全库存 * 1.5
- 高预警: 库存 < 安全库存 * 2.0
```

**AI可能会提问**:
- "响应格式中是否还需要其他字段?(如商品图片、最后入库时间等)"
- "是否需要实时查询库存还是可以使用缓存?"

## ⚠️ 注意事项

### 1. 信息提供建议

- **越详细越好**: 提供的信息越详细,填充的准确度越高,需要的提问次数越少
- **关键信息优先**: 接口路径、请求参数、响应格式是最关键的信息
- **业务规则明确**: 业务规则越明确,后续实现越顺利

### 2. 填充结果检查

- **必须人工检查**: AI填充的内容可能不完全准确,务必人工检查
- **重点检查项**:
  - 接口文档的参数和响应格式
  - 业务规则是否完整
  - DDD分层设计是否合理
  - 技术细节是否准确

### 3. 模板文件管理

- **每次使用前复制**: 从 `_TEMPLATE-任务模板/` 复制一个新文件夹
- **文件夹命名**: 建议使用 `PLM-{编号}-{功能简述}` 格式
- **不要直接修改模板**: 保持 `_TEMPLATE-任务模板/` 目录的干净

### 4. 与下游 Skill 的配合

- **先填充,后分析**: 先用 `soms-template-filler` 快速填充,再用 `soms-requirement-analysis` 深度分析
- **检查后再传递**: 填充完成后检查并补充,再使用 `soms-requirement-analysis`
- **迭代优化**: 如果发现填充结果不理想,可以重新运行 `soms-template-filler`

## 🆘 常见问题

### Q1: 如何准备任务文件夹?

**A**: 从 `_TEMPLATE-任务模板/` 复制一个新文件夹:
```bash
cd .claude/mydocs/tasks/
cp -r ../_TEMPLATE-任务模板 PLM-338429-引流活动商品列表
```

### Q2: 需求描述应该包含哪些内容?

**A**: 至少包含:
- 功能是什么 (功能概述)
- 接口路径
- 请求参数
- 返回内容
- 涉及的业务实体

其他信息(业务背景、业务规则、技术细节等)可选,AI会根据需要提问。

### Q3: AI提问太多,怎么办?

**A**: 提供更详细的需求描述,减少AI需要提问的次数。可以参考"示例1: 完整详细的描述"。

### Q4: AI填充的内容不准确,怎么办?

**A**: 有两种方式:
1. 直接编辑对应的 `.md` 文件进行修改
2. 删除填充内容,提供更详细的描述重新运行 Skill

### Q5: 可以跳过这个 Skill,直接用 soms-requirement-analysis 吗?

**A**: 可以,但前提是你已经手动填写好了6个PRD模板文档。如果你不熟悉PRD结构或想节省时间,建议先用 `soms-template-filler`。

### Q6: 填充后还需要做什么?

**A**:
1. 检查填充的内容,补充或修改不准确的部分
2. 使用 `soms-requirement-analysis` 进行深度需求分析
3. 使用 `soms-code-implementation-v2` 实现代码

## 💡 最佳实践

### 1. 需求描述结构化

建议按以下结构组织需求描述:

```
基础信息:
- PLM任务号: PLM-xxxxx
- 功能: xxx
- 需求来源: xxx
- 业务背景: xxx

接口信息:
- 接口路径: /api/xxx
- 请求方法: POST
- 请求参数: xxx
- 响应格式: xxx

业务信息:
- 业务实体: xxx
- 业务规则: xxx
- 业务流程: xxx

技术信息 (可选):
- 涉及模块: xxx
- 外部服务: xxx
- 数据库表: xxx
```

### 2. 分步骤填充

如果需求很复杂,可以分步骤填充:
1. 第一次: 填充基础信息和接口信息
2. 检查并补充
3. 第二次: 添加业务规则和技术细节
4. 最终检查

### 3. 知识库复用

如果需求涉及已有的业务规则或技术规范,可以在需求描述中提及,AI会参考知识库进行填充。
